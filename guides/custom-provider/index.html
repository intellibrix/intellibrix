Writing a custom provider

A Provider does exactly one model step per call. The agent loop owns iteration, tool dispatch, approvals and memory, so a provider is small.

A full provider

Section titled “A full provider”

generate receives the model name, system prompt, messages and the tools on offer, and returns the assistant message, a finishReason, and optionally usage. stream yields text-delta and tool-call events and ends with a finish event carrying the same StepResult.

To support tools, translate req.tools into your service’s format and map its tool-call response into tool-call parts (toolCallId, toolName, input) with finishReason: 'tool-calls'. If your model prints calls as text instead, wrap it with textToolCalls.

Always honour the abort signal

Section titled “Always honour the abort signal”

Pass req.abortSignal to your HTTP client. It is how Ctrl+C in a terminal REPL, request cancellation and run timeouts stop an in-flight model call.

Test it

Section titled “Test it”

Use MockProvider as a reference for the expected shape, and run your provider through a few tests with scripted tool calls.
